# CPU 按评分目标裁剪动作（2026-10-04）

CPU 搜索现在根据评分及筛选需求，跳过不消费的轮转输出，并为单技能目标保留足够长的默认动作前缀。最终候选仍通过完整模拟重建展示行。

本轮百万组合 BASIC、战斗 CD 的热运行均值分别减少约 **49.8%**、**48.6%**，真实默认任务减少约 **18.2%**。60/60 次正式搜索完成，49,272 个候选重算通过，45,166 对排序分数完全相同。未裁剪的 COMBO 对照组也有 6%–8% 的改善，存在环境或运行时波动，不能将均值变化全量归因为裁剪或推广为全设备收益。

这是 [CPU Worker Top K](cpu-topk-performance.md)之后的独立阶段。基线已包含 Top K，不能把本轮结果归因于两项改动的总和。代码、原始测量和参考版本保存在 Git 忽略的 `output/performance-cpu-objectives-20261004/`。

## 改动范围

- `cpuActionPlan.ts` 按请求生成默认动作数和轮转动作数；Worker 仅改变两个循环的上界。
- 属性和 EHP 排序保留全部默认动作；单技能排序保留目标及后续技能筛选所需的前缀。战斗属性或 EHP 筛选要求保留最后一个默认动作。
- CPU 筛选以 `min === 0 && max === MAX_INT` 为禁用条件，负数下限同样参与依赖判定。
- `COMBO`、`COMBO_HEAL`、`COMBO_SHIELD`、`COMBO_BUFF`、trace 和无法定位的目标保留完整动作。
- 保留 CPU 原先的轮转先于默认动作顺序，全部命中及动作/命中寄存器编号不变。治疗转伤害读取同动作前序命中的依赖完整保留。
- 完整 context、初始化、浮点舍入、Top K、线程数、批次大小和主线程最终完整模拟均未改变。没有裁剪动作内部的计算。

CPU 与 GPU 目前各自维护执行计划。CPU 严格匹配自身的过滤激活条件，且执行顺序与 GPU 不同；本轮不改变 GPU 计划和公式。

## 性能结果

冻结顺序为 **旧 1 → 新 1 → 新 2 → 旧 2**。每组每场景三次，每个版本每场景首次 n=2、热运行 n=4，合计 60 次正式搜索。每个场景/组使用独立 Edge 浏览器，计时从提交到观察到完成，10 ms 轮询；候选重算在计时之外。两版安装同样的消息计数器，均不带阶段计时探针。

| 场景                           | 旧版首次均值 | 新版首次均值 | 旧版热运行均值 | 新版热运行均值 | 热运行耗时减少 |
| ------------------------------ | -----------: | -----------: | -------------: | -------------: | -------------: |
| 百万 COMBO，K=10，对照         |      2.794 s |      2.450 s |        1.932 s |        1.819 s |           5.8% |
| 百万 COMBO，K=1024，对照       |      2.690 s |      2.434 s |        1.901 s |        1.741 s |           8.4% |
| 真实默认 TALENT_SHIELD，K=1024 |     10.937 s |      8.697 s |        9.659 s |        7.900 s |          18.2% |
| 百万 BASIC，K=1024             |      2.630 s |      1.584 s |        1.757 s |        0.882 s |          49.8% |
| 百万战斗 CD，K=1024            |      2.413 s |      1.505 s |        1.729 s |        0.889 s |          48.6% |

百万场景沿用前轮镜流的受控合成库存，每槽 10 件；BASIC/CD 是明确设置的评分目标。真实场景为未缩减库存、未改默认筛选的 `8004`，12,625,614 个组合。输入 SHA-256、完整 settings、每次原始时延和结果保存在证据中。本轮是一项真实默认任务及受控场景验证，不是全账号完成度测试。

环境为 Windows、Intel i5-12500H、16 个逻辑 CPU、Node 26.10.0、约 15.7 GiB 系统内存。线程池上限 10，批次上限 150,000；构建、测试与性能测量串行。未隔离系统后台负载、锁定频率或清理驱动/浏览器缓存。COMBO 保留全部动作，其时延变化不能作为动作裁剪收益；两版交替运行缓解但没有消除漂移。

这一阶段在保留完整结果的同时取得了可重复观察到的场景改善，保留实现。没有承诺稳定尾延迟、所有角色或其他处理器上的同等提速。

## 改动前的阶段诊断

通过仅用于诊断构建的 Vite Worker transform，每 64 个组合取一个计时样本，并在提前退出时记录已经进入的阶段。五个固定场景各运行三次；下表合并后两次重复运行。

| 场景                   | 索引及套装检查 | 基础属性及筛选 | 轮转动作 | 默认动作 | EHP、筛选及 Top K |
| ---------------------- | -------------: | -------------: | -------: | -------: | ----------------: |
| 百万 COMBO，K=10       |           7.0% |          19.9% |    43.1% |    23.2% |              6.8% |
| 百万 COMBO，K=1024     |           6.2% |          20.7% |    42.9% |    23.2% |              7.1% |
| 真实默认 TALENT_SHIELD |           9.8% |          29.8% |    16.5% |    34.1% |              9.8% |
| 百万 BASIC             |           6.0% |          18.9% |    43.3% |    24.1% |              7.7% |
| 百万战斗 CD            |           5.6% |          19.5% |    43.7% |    24.9% |              6.4% |

这些是**抽样阶段经过时间的占比**，包含计时器粒度、探针和调度噪声，不是 CPU 时间，也不是预测的总耗时降幅。固定步长样本不代表所有组合分布。上下文克隆、发送和主线程结果重建不在 Worker 计时内。多 Worker 的时间总和不能当作搜索耗时。正式性能测量使用不带探针的构建。

## 正确性验证

定向单元测试和本地参考共 **141 项通过**：48 项仓库测试、74 项本轮完整动作 Worker 对照测试、19 项前轮旧 Worker 参考测试。74 项中包括全部 45 个此前可用的原始默认配置（使用每槽两件的受控小空间），不表示完成了 45 个真实大库存搜索。

独立六重循环完整模拟用于核对 Top K 分数和最终行。覆盖技能上下限、EHP 上下限、战斗属性筛选、忆灵显示、负分、float32 舍入门槛、零分同分、短尾、乱序批次、不足 K、空结果及超过 `2^32` 的索引。新增遐蝶单技能治疗、忆灵治疗转伤害和非零轮转治疗用例。

正式测量的 **49,272 个候选**逐项独立重算，适用字段最大相对误差约 **5.90e-8**，低于 `1e-5`；同分允许不同候选身份，但每次结果必须唯一且满足遗器可行性约束。每个场景的其他 11 次结果与一次旧版参考比较，**45,166 对排序分数最大误差为 0**。沿用前轮字段口径：没有忆灵时排除不适用的忆灵占位字段，索引和库存权重不属于模拟数值比较。

**32/32 浏览器测试通过**：11 项 CPU 目标、11 项 GPU 目标、10 项通用自动化，包含取消、失败和套装路径回归。快速类型检查、自动化类型检查、生产构建及两份基准构建退出 0；本轮修改文件的 Lint 为 0 警告、0 错误。大空间与现有完整算法的一致性不等于独立穷举最优性证明。

本轮直接参考是保存的裁剪前 Top K Worker，逐批比较实际返回分数。另运行的 19 项历史旧 Worker 参考沿用[前轮说明](cpu-topk-performance.md#正确性与原版对照)：旧完整行 Worker 关闭其旧门槛，再按 packed float32 分数筛选，不能称为旧门槛行为逐项相同。

首次新增非零轮转治疗测试采用 simple rotation，没有治疗动作，因此正值断言失败；随后将测试明确设置为包含治疗和忆灵技能的 advanced rotation，生产公式未修改。诊断脚本首次也有一处语句边界错误，在搜索开始前失败。两次失败的日志均保留。

独立只读代码审查未发现严重或重要问题；审查未运行测试。
