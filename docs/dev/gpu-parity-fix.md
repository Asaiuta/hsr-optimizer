## 原版与修复

反例装备 Guard of Wuthering Snow 两件、Ever-Glorious Magical Girl 两件、Punklorde Stage Zero 两件，没有装备 Sigonia。魔法少女基础暴伤为 `0.16`，未激活的 Sigonia 默认 4 层也对应 `0.04 × 4 = 0.16`。移除未激活的 Sigonia 分支或改成显式数值匹配乘法，均恢复该反例评分；修复前改为单周期也正确。首个轮转普攻出现偏差，后续同类普攻正常。

唯一生产修复位于 `src/lib/sets/ornaments/SigoniaTheUnclaimedDesolation.ts`：将包围加成的 `if (ornament2p(...))` 改为 `0.04 * stacks * f32(ornament2p(...))`。未匹配时加零，匹配时仍每层增加 4% 暴伤。CPU 公式保持不变。

证据支持这一等价改写在当前设备上消除了故障，**尚未证明具体 GPU 驱动/编译器缺陷，也未定位首次引入的历史版本**。本轮设备为 Edge WebGPU、`nvidia / ampere`；不将此结果外推为所有设备验证。

## 可持续回归

```powershell
npm run gpu:test
```

需要 Node 26、项目依赖、Edge 和可用 WebGPU，端口 4177。`HSR_BROWSER_CHANNEL` 可选择其他已安装的 Playwright 浏览器通道。测试明确要求 GPU，缺失时失败，不静默跳过。

`tests/Gpu/` 直接调用生产管线并读取 compact 缓冲分数，在进入结果展示的 CPU 重算前比较完整 CPU 模拟。夹具仅保留反例的六件遗器和计算设置，移除了账户关联标识：普通枚举复制六件遗器以保留原着色器槽位尺寸，仅提交索引 18,113,941；tuple 路径使用单分配、零起点的 64 组合夹具并检查全部返回分数。这些是定向回归，不能计入真实库存覆盖。

矩阵为普通/tuple 两路径 × COMBO/BASIC/战斗 CD 三目标 × Sigonia 0/1/2 件 × 0/4/10 层，共 18 个测试、54 组场景、1,755 个原始 GPU 分数对照。另检查未成套时层数不改变 CPU 结果、成套时加成随层数增长，战斗 CD 的增量明确为 `0.16/0.40`。所有场景保留 256 周期。

同一保留测试已在隔离构建中换回修复前 Sigonia 源码：`naive COMBO, 0 Sigonia pieces` 于 4 层失败，误差 `0.008624128192850715`；修复版矩阵通过。旧代码测试退出 1 是预期的评分失败，不与首次测试配置错误混同。

最终矩阵最大相对误差 `2.6650581560107277e-7`，0 跳过。另将冻结修复后着色器按生产声明切换到 storage 预计算缓冲，独立重放两条候选；反例为 `1,407,098.375`，对照为 `1,392,529.5`，均在误差门槛内。这不是 Firefox 或其他设备的实际验证。
