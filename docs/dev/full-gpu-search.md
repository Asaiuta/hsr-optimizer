## 测量边界与瓶颈

设备为本机 Edge WebGPU、NVIDIA Ampere。隔离构建仅加入主机观测和结果重算前的原始候选捕获，未改动正式调度或生产 WGSL。每次使用独立浏览器，未清理磁盘或驱动着色器缓存。

耗时是从提交任务到轮询发现产品完成的墙钟时间，包含管线编译及正常结果处理，不含存档导入和最后独立候选审计；轮询间隔为 1 秒。它不是纯 GPU 时间，也不能标为强制冷缓存结果。

银狼累计 map 等待 161.132 s、主机回读处理 0.166 s、管线编译 2.809 s；开拓者分别为 453.020 s、2.222 s、0.410 s。map 等待包含 GPU 执行、复制和调度，并与其他工作重叠，不能称为纯传输成本或直接相加。完整任务未记录每次 dispatch 的 GPU 时间戳。

两次溢出带来的额外提交量均很小；主机结果队列处理也只占很小部分。因此当前证据不支持继续优先修改溢出二分或 CPU 结果堆。主要时间在 GPU 执行及其等待链上，进一步分离计算和调度需要专门测量。

## 默认动作裁剪筛选

源码审查确认：此银狼 COMBO 没有默认动作输出消费者，默认动作容器及条件状态独立，基础属性和套装指针没有写入。候选仅删除生成 WGSL 主函数中的 5 个默认动作调用，保留全部函数、16 动作预计算布局、轮转索引和 Sigonia 修复。没有把动作数组重排或缩短。

性能筛选先固定 5% 收益门槛，使用原四个 33,554,432 组合窗口、完整搜索已得到的最终 Kth 门槛、7 轮交替原版/候选顺序，以及每变体一次不计入收益的预热。28 对正式 GPU 时间戳测量的每轮四窗总时长，中位改善为 -2.3414%，即候选约慢 2.34%；部分轮次波动，不构成稳定提速，因此停止这条生产修改。

该最终全局门槛使四个窗口都没有返回候选：包括预热共 29 对计数检查，但评分比较实际是 **0 条**。这是固定高门槛下的计算耗时筛选，不能声称候选评分等价已验证。原 `screen.json` 的 `passedPairs=29` 只表示计数检查；`summary.json` 明确分开正式计时、预热与比较分数数量。未采用的候选不替代两次全任务使用的基线。

## 整块剪枝的下一步边界

此次只完成源码可行性审查，未实现或宣称剪枝可用。开拓者防御型护盾比任意 COMBO 更适合作为第一项有严格上界的研究：只有证明一个部分配装块的所有补全分数都低于已保留第 K 名，才允许跳过。

上界必须覆盖圣骑士二件防御与四件护盾加成、贝洛伯格在战斗命中率达到 50% 时新增的防御、光锥/队友效果及浮点舍入。仅取剩余遗器最大防御值会漏掉条件激活。未知规则应退回完整枚举，不能用未经证明的预选代替正确性。详细源码位置和验收条件见 `pruning-feasibility.md`。
