# 真实库存的大规模搜索口径（2026-10-04）

后续验证：[正式 GPU 全量搜索](full-gpu-search.md)已跑完最大默认银狼任务，以及仅将强化门槛改为 +0 的开拓者 4.31 万亿组合实验。该结果仅覆盖这两个具体输入，以下保留首次规模审计时的计数与历史验证状态。

原聊天确实提过约 **5,995 万亿**组合：那是 2,591 件真实遗器的六槽原始笛卡尔积。本轮使用当前源码重新核对原始存档与默认存档，确认了这个数字。此前 CPU 动作裁剪测量中的真实任务只有 12,625,614 个组合，恰好是 45 个可用默认任务中最小的一项；其改善不能代表千亿或万亿规模完成能力。大规模场景的优化优先级应以减少需要计算的组合和每组合工作为主，GPU 编译缓存后移。

本轮完成计数与源码审计，没有启动全量搜索，也没有修改用户存档或生产搜索逻辑。证据目录：`output/scale-audit-20261004/`。

## 单项设置的规模影响

另在隔离 Node 进程中，仅用于计数地改变一个参数，保持库存及其他参数不变。这些是敏感性实验，**不声称它们是历史实际任务**。

| 参数变化             | 单任务达到万亿的数量 |                              单任务范围 |           45 任务合计 |
| -------------------- | -------------------: | --------------------------------------: | --------------------: |
| 不改现存设置         |                 0/45 |              12,625,614–281,113,196,980 |     1,199,669,661,644 |
| 仅强化门槛 +9 → +0   |                45/45 | 4,311,364,200,000–1,398,855,215,348,640 | 5,192,510,384,560,814 |
| 仅关闭角色优先级排除 |                 0/45 |             229,547,520–450,644,705,280 |     4,127,629,584,384 |

纳入低强化真实遗器即可产生单任务万亿以上的搜索空间，无须合成或复制遗器。计数仍早于战斗属性筛选及动态计算；本次任务没有套装组合限制，因此槽位乘积没有额外套装约束折减。不得混淆原始库存乘积、单项过滤后的候选空间、计算中通过筛选的组合数量、实际已搜索数量。

## 大任务验证缺口

历史默认任务报告中，1512 的 92,454,912,000 个组合与 1506 的 281,113,196,980 个组合均触及 120 秒观察预算后取消。取消前报告进度分别约为 0.58% 和 0.12%；这些是旧构建、旧设备环境的记录，不能当作当前速度或完成时间估计。

近期 CPU 动作裁剪的 60 次正式任务与 49,272 个候选重算支持该轮场景的正确性和性能结论，但没有补上千亿/万亿规模完整搜索的证据。小空间穷举、分块测量、长任务部分进度和完整搜索必须分别报告。

## 修正后的优化顺序

后续[大任务分块诊断](large-search-diagnostic.md)曾在首个 33,554,432 组合窗口发现 GPU 评分差异：1,024 条保留候选中 212 条未通过完整 CPU 重算，性能协议按规则停止。现已完成[评分修复与原版对照](gpu-parity-fix.md)，全部冻结分块协议通过；千亿/万亿全量搜索及完整任务性能结论仍未验证。

1. **先建立原始大任务的分块诊断。** 以 1506 的 COMBO 与 1303 的战斗 BE 为不同计算类型的固定默认输入，保留全部候选和原始设置。分别记录分块覆盖区间、每组合计算、溢出重跑和 GPU 回读；分块完成不能写成整个任务完成。
2. **研究可证明安全的整块排除。** 对部分槽位组合计算剩余槽位的评分上界或约束可行性界，只有能证明整块不可能进入 Top K 或通过筛选时才跳过。先限定到能建立有效界的评分/条件组合，无法证明的路径继续完整计算。角色条件阈值、套装切换、增益上限和浮点舍入都必须进入证明及对照验证。
3. **降低 COMBO 的单组合成本。** 当前最大的默认任务多数是 COMBO，上一轮裁剪对它们仍保留全部动作。可评估没有默认动作消费者时省去默认动作计算，并继续复用固定槽位属性、套装状态和相邻组合的解码结果。保持完整结果重建、过滤语义及 COMBO_BUFF 的特殊增益语义。
4. **按大任务诊断结果优化 GPU 执行和结果选择。** 确认瓶颈后再调整批次、工作组、溢出处理或局部分层 Top K；减少结果传输不等于减少评分计算次数。
5. **设备/管线复用及小任务准备优化后移。** 它们仍有价值，但主要降低启动或调度成本，不能解决枚举规模本身。

45 个默认任务全部没有套装限制，因此“仅枚举合法套装组合”无法直接减少这些默认空间；它适用于本来就有套装约束的任务。不能为了获得漂亮时延额外加入套装、强化、每槽候选数量或权重阈值限制。未经证明的启发式预选如另行研究，应明确其可能改变最优结果。

这些是有源码依据的后续方向，本轮没有实现分支剪枝，也没有宣称万亿级搜索已可实用完成。
