# 大任务分块诊断：GPU 评分差异（2026-10-04）

后续状态：已完成[GPU 评分修复与原版对照](gpu-parity-fix.md)，原版同样复现，修复后全部冻结窗口通过。下文保留首次诊断时的失败与未完成状态，作为历史证据。

本轮在真实默认库存的大窗口中发现 GPU 评分不一致，按冻结规则停止性能诊断。银狼 LV.999 的第一个 33,554,432 组合窗口返回 1,024 条候选，其中 **212 条**与完整 CPU 模拟的相对误差达到或超过 `1e-5`，最大约 **1.0773%**，并出现排名互换。问题尚未修复；本轮没有修改生产计算源码，没有据此宣称提速或完整搜索可用。

这接续[搜索规模审计](large-search-scale.md)。当前优先项改为修复并验证 GPU 评分一致性；通过后再恢复相同大任务协议，测量计算、回读和溢出成本。

## 冻结输入与执行范围

输入为 `output/default-account-20261003/default-save.json`，SHA-256：

```text

```

原库存、默认筛选、遗器顺序和完整组合总数保留。K 固定为 1,024，分别计划诊断银狼 LV.999（1506，COMBO，281,113,196,980 组合）和阮·梅（1303，战斗 BE，116,889,948,868 组合）。设备报告为 `nvidia / ampere`，支持 GPU 时间戳查询。

每角色取开头、四分之一、中间、末尾四个固定区间；先各做 65,536 组合的 CPU/GPU 对照，再做两轮各四个 33,554,432 组合的 GPU 窗口，最后各做 1,048,576 组合的 CPU 阶段采样。每轮 GPU 队列清空，轮内门槛只来自已实际抽样的窗口，不代表未知的完整前缀。发生评分差异即停止，不改变库存、窗口或筛选来继续计入通过结果。

小窗口最大排序分数相对误差为 `4.2342475255208686e-7`，各自 GPU 候选也通过完整 CPU 模拟重算。首个大窗口仅占银狼完整任务的 **0.0119363%**。正式协议已处理的区间并集为 33,751,040 个组合：开头小窗口包含在大窗口中，另外三个小窗口各 65,536。此计数表示处理范围，不表示该范围评分正确，更不表示任务完成。随后故障定位的重叠区间和重复执行不计入此覆盖数。

隔离入口只执行指定全局索引区间，运行结束清理自己的 Worker/GPU 资源；没有向产品写入整任务 `completed` 状态。

## 已定位到的边界

对索引 18,113,941 保持完整库存和所有默认条件，仅调整诊断执行位置与着色器形式：

| 隔离条件                              |       该候选的 GPU 分数 | 结果                                         |
| ------------------------------------- | ----------------------: | -------------------------------------------- |
| 正式路径，256 周期，单独提交 1 个组合 |            1,419,233.75 | 仍有差异，排除必须经过大窗口或前一组合才触发 |
| 两个不同起点的 65,536 组合窗口        |            1,419,233.75 | 稳定复现                                     |
| DEBUG，单周期，完整容器输出           | 与 CPU 在 `1e-5` 内一致 | 是另一种生成/编译形式，不等于正式路径通过    |
| 正式输出，诊断性改为单周期            |           1,407,098.375 | 该单组合通过，未将其视为生产修复             |
| 原有 storage 预计算缓冲路径，256 周期 |            1,419,233.75 | 未消除差异                                   |

进一步按动作输出，轮转中的第一个普攻（`dmg5`）得到 252,128.75，CPU 为约 239,993.48；后续同类普攻 `dmg9`、`dmg12` 为约 239,993.45，正常。多出的伤害近似等于该次普攻额外获得 0.16 暴伤。

该候选配装为 Guard of Wuthering Snow 两件、Ever-Glorious Magical Girl 两件、Punklorde Stage Zero 两件。生成源码中魔法少女两件套只有一次 `+0.16`，没有找到合法的重复加成。另一个输出探针的基础暴伤正确，但动作容器多出 0.16；探针会改变编译器保留的变量，不能直接推断未插探针时所有动作都受影响。

以下隔离修改均未消除差异：每轮重新读取遗器与套装掩码、基础属性按值传递、直接读取属性指针、布尔转换改 `select`、暴伤加成改分支、标量遗器暴伤求和、动态循环上限、提取基础属性计算函数、条件状态按动作拆分、移除该样本未被读取的命中寄存器写入。它们均仅存在于隔离构建，没有写入生产源码；移除寄存器写入也不适用于依赖先前治疗等命中结果的通用路径。

现有证据将问题限定到此设备上多周期正式着色器的执行形式，**尚不能认定具体驱动/编译器缺陷，也未确定问题从哪个历史版本引入**。不采用改分数、放宽误差阈值或限制用户套装的补丁。后续应保留此反例，继续缩小 WGSL 复现并验证修复，再重跑全部冻结窗口。

## 失败窗口的诊断记录

虽然评分失败，执行遥测仍保留用于追踪：26 次 dispatch、12 次溢出，累计提交区间长度 100,638,722，相当于窗口的约 2.9993 倍。主机搜索计时 142 ms，GPU 时间戳累计约 88.21 ms，结果映射等待累计约 138.20 ms，主机处理约 1.30 ms。

这些是**评分错误运行的遥测**，不列为有效性能结果，不外推完整千亿/万亿任务耗时。映射等待包含 GPU 执行、复制和调度，与 GPU 时间重叠，不能相加。隔离入口也没有复现正常整任务双缓冲流水线，不能据此判断正式流水线瓶颈。CPU 阶段采样未执行，当前无法给出 COMBO 各 CPU 阶段的占比。
