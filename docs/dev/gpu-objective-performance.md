# GPU 按目标裁剪动作：实现与验证（2026-10-04）

GPU 现在根据排序目标和筛选依赖，只生成所需的动作前缀。本机 NVIDIA Ampere 的三个真实库存场景中，首次运行平均缩短 **0.49–0.69 秒**；热运行没有一致提速，其中布洛妮娅平均慢约 **65 ms**。保留这项改动的依据是明确减少无用着色器和预计算数据、首次运行改善，以及当前正确性检查通过；不能把它描述为普遍降低 GPU 内核耗时。

本轮接续[溢出分块优化](gpu-overflow-performance.md)，对照版本已经包含该优化。真实账号输入、隔离构建、完整候选和日志保存在 Git 忽略的 `output/performance-objectives-20261004/`。

## 实现范围

`gpuActionPlan.ts` 统一决定保留多少动作，供动作调用、条件函数和预计算缓冲共同使用，替代原来仅在动作调用中判断提前结束的位置。

- 基础属性和 EHP 排序保留全部默认动作，省去后续轮转动作。
- 单技能排序保留到目标动作；如果启用后续技能筛选、EHP 筛选或战斗属性筛选，则延长到相应依赖。
- COMBO、COMBO_HEAL、COMBO_SHIELD、COMBO_BUFF 和 DEBUG 保留全部动作。
- 保留原动作顺序、标识符、寄存器布局及完整 CPU 上下文。最终候选仍通过完整模拟补齐所有输出。

这次没有裁剪单个动作内部的命中和条件计算，也没有改变评分公式、默认筛选、K 值、溢出调度或 CPU Worker 路径。基础属性目标仍保留默认动作计算；更细粒度的依赖裁剪尚未实现。

对真实库存中 45 个有效默认配置做前后着色器生成检查：**27 个 COMBO 配置逐字节相同，18 个其他目标减少了源码和预计算数据**。这是生成检查，不是 45 个角色的驱动执行验证。检查使用同一测试遗器输入和 storage 地址空间；真实浏览器性能测量另行执行。

| 本轮性能场景  | 生成动作 | 预计算缓冲字节 |  着色器源码字节 |
| ------------- | -------: | -------------: | --------------: |
| 知更鸟 / ATK  |    5 → 4 |    1620 → 1296 | 149200 → 125729 |
| 符玄 / EHP    |    5 → 4 |    1620 → 1296 | 150272 → 126653 |
| 布洛妮娅 / CD |    5 → 4 |    1600 → 1280 | 147382 → 123628 |

这些缓冲仅减少 320–324 字节；源码约减少 16%。不能据此宣称整体内存或显存明显下降。

## 真实性能

冻结协议采用 **旧 1 → 新 1 → 新 2 → 旧 2**。每组每角色运行两次：独立浏览器中的首次运行和同浏览器内的重复运行。每版本每角色首次、热运行各 n=2，总计 **24 次搜索，24 次完成**，没有超时或跳过。

固定 GPU Stable、1024 个结果和原版默认筛选。输入存档 SHA-256 为 `ffe598893f0ea1fe614dd1b43eb52e532c41c2892c3c95cf96e8c10065165042`。全部运行报告的适配器均为 `nvidia / ampere`，本机为 RTX 3060 Laptop GPU；没有混入之前 Intel 核显的数据。

首次运行均值分别从 1.772 → 1.085 秒、1.745 → 1.194 秒、2.037 → 1.545 秒，减少约 0.687、0.551、0.492 秒。没有清除磁盘和驱动缓存，因此不能称为完全冷启动。计时从提交前到观察到终态，包括请求准备、编译和结果处理，没有单独测量内核时间，无法把改善全部归因于编译。

100 ms 轮询对亚秒任务影响明显。符玄和布洛妮娅的热运行均值差均小于一个轮询周期，当前样本无法区分小幅变化与波动；布洛妮娅的负面观测仍如实保留。没有通过更换输入、改参数或补选更有利运行来替代冻结结果。测试、构建与基准顺序执行，未隔离系统后台负载。

## 正确性和验证边界

大任务的每次输出均为 1024 个不同且符合原库存筛选的组合。独立检查了六部位、主属性、强化、星级和角色优先级占用限制，并重新计算三个输入空间的组合数。

- **24,576 个候选**重新完整模拟，全部数值输出的最大相对误差为 **0**；搜索编号和库存权重不属于模拟输出。
- 使用实际战斗排序列 **xATK / EHP / xCD**，对每角色其他七次运行与一次旧版参考逐位比较，**21,504 对分数完全一致**。同分组合身份可以不同，但单次结果不允许重复。
- 新增 **8 项真实 GPU 浏览器测试**全部通过、无跳过。每项穷举 64 个组合，检查前 K=7 分数、筛选条件、唯一性和完整返回字段，覆盖基础／战斗显示、后续伤害和 EHP 依赖、COMBO 和忆灵显示。
- **19 项定向单元测试**通过，包含 12 类属性／EHP 目标、四种组合目标保留全部动作、条件函数完整性、缓冲大小和 DEBUG 回归。
- 已有 **10 项自动化浏览器回归**在同一候选生产代码上通过，覆盖 CPU/GPU/tuple 的小库存排序、取消和空结果等。

COMBO_HEAL、COMBO_SHIELD、COMBO_BUFF 的全部动作保留通过结构检查；当前自动化结果没有导出这三项全局数值，因此本轮没有将它们记为浏览器数值验证通过。十亿级任务采用旧版对照和返回候选重算，并非整个空间的独立最优性证明。Intel、其他 GPU、全部角色数值正确性和长期压力运行尚未在本轮覆盖。

独立只读代码审查没有发现本次引入的具体正确性问题。应用快速类型检查、自动化类型检查、生产构建和隔离基准构建均退出 0。Lint 为 0 警告、0 错误；定向格式和差异检查通过。构建仍有既有第三方注释和大包体提示。

浏览器测试开发时发现并修复了测试入口错误：伤害／EHP 筛选需从存档表单设置，查询结果位于 `settings.ratingFilters`，且 UI 会舍入小数。最终使用两个不同分数之间的整数阈值，并断言筛选实际减少可行集合。早期失败日志保留，未计入通过分母；没有为适配测试修改产品筛选接口。
