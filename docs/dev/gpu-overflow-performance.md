# GPU 溢出分块：实现与验证（2026-10-04）

无套装约束的 GPU 搜索已改为“小批建立分数门槛，溢出区间递归拆分”。真实库存的 Intel 核显大任务平均从 **289.71 秒降至 235.44 秒，耗时减少 18.7%**。但这不是普遍提速：NVIDIA RTX 3060 的两个小任务在本轮重复运行中分别慢约 **47 ms、114 ms**。改动通过当前正确性检查，仍有小任务调度开销的取舍，不能称为全设备性能零回归。

本文接续[性能基线](performance-baseline.md)。详细账号输入、逐项候选和完整日志保存在 Git 忽略的 `output/performance-overflow-20261003/`，没有放入公共文档。

## 改了什么

原有无套装约束路径将溢出批次的部分结果入队，在主遍历结束后反复重算整批，通过索引集合避免重复。默认最多约 3355 万组合的单批与 4096 项结果缓冲区相差很大；整批重算可能占据主要耗时。

现在先计算不超过结果缓冲区容量的小批，以实际候选建立前 K 名门槛。后续仍采用双缓冲；如果一个区间的输出溢出，就丢弃不完整输出，将区间分成互不重叠的左右两半，并在原缓冲中依次解决。只有完整返回的叶区间入队，进度在对应父区间解决后才前进。

- `src/lib/gpu/webgpuOptimizer.ts`：新增种子批次和 `resolveNaiveRange`，移除该路径的事后整批重访及重复索引集合。
- `src/lib/gpu/webgpuInternals.ts`：按实际区间长度计算工作组数量。
- `src/lib/gpu/webgpuDataTransform.ts`：接受区间长度并限制最后一个区间，沿用现有大索引拆解方式。

没有改变评分公式、默认筛选、结果数量、GPU 缓冲区容量或套装约束的 tuple 调度算法。对照是本地改动前后的版本，不是未修改上游与本地所有自动化改造的对比。改动前的三个文件和两份隔离构建保存在本地证据目录。

正确性依据是：完整叶区间覆盖整个输入且互不重叠；区间长度缩小到缓冲区容量时，不可能产生多于容量的候选；前 K 名队列的最低分只会提高。阈值过滤可以舍弃无法进入前 K 名的分数。同分候选的具体身份和排列不作跨运行承诺，但结果中不得出现重复组合。

## 正确性与回归

纳入比较的是 4 次 Intel 大搜索和 24 次 NVIDIA 小搜索，共 **28 次全部完成**。每次均保留 1024 个不同组合：

- **28,672 个候选**逐项重新模拟，目标分数最大相对误差为 0。
- 每个硬件组、每个角色取一个旧版结果作参考，将其他运行排序后的分数逐位比较：**25,600 对全部相同**。允许同分组合不同。
- 独立小库存穷举包含梯度分数和全部同分两组，各 **15,625 个组合**；每组验证 K=1、10、100、1024，共 **8 项、2270 个返回候选**，与穷举模拟的前 K 名分数一致，最大相对误差为 0。

独立穷举结果来自原聊天保存的 GPU 运行，本次校验其报告与冻结文件；它覆盖小规模最优候选完整性。真实大任务的候选重算及旧版对照并不是对十亿级空间的独立穷举证明。

新增及更新的测试覆盖密集溢出、尾区间、同分、稀疏和无结果、结果少于 K、读取期间取消、另一缓冲在途时取消、错误计数、超过 32 位的组合起点；浏览器回归包含 CPU/GPU 单组合、GPU 取消后重启与空结果，以及 CPU/GPU/tuple 与 64 组合穷举对照。

独立只读代码审查未发现本次引入的阻断问题，检查了真实 WGSL 进位与区间上限、阈值单调性、双缓冲队列顺序和取消。单元测试替换了 GPU 提交函数，因此工作组计算与驱动实际执行之间仍主要由真实 GPU 搜索验证。

## 内存与进度边界

Intel 大任务结束时的主渲染进程私有内存，旧版约 145.9–150.8 MiB，新版约 136.1–153.5 MiB；GPU 进程约 193 MiB。两组范围重叠，没有证据宣称稳定降低内存。实现未增加 GPU 结果缓冲区；递归深度随区间对半缩小，且去掉了无套装约束路径的重复索引集合。

这些是任务结束边界的 OS 快照，不是连续峰值或显存测量。没有强制 GC，不能把 JS 主线程堆等同于整个应用内存。基准的进度计数仍有既有预热显示偏移；搜索完成继续以 `completed` 终态判断。

原聊天 `small-after-1` 因浏览器/进程采样错误中断，未完成结果验证；试跑和该不完整文件保留，但没有纳入上面的比较分母。补测四个分组的进程退出码全部为 0。
